# اختبار هاتف ARM64

## التجهيز

1. استخدم هاتف Android 10 أو أحدث بمعمارية arm64-v8a، ومساحة فارغة لا تقل عن 1 جيجابايت.
2. انقل APK التجريبي إلى الهاتف وافتحه، واسمح بالتثبيت من مدير الملفات عند طلب الهاتف ذلك.
3. أو استخدم Android Platform Tools: فعّل خيارات المطور وUSB debugging، وصل الهاتف ووافق على بصمة الكمبيوتر، ثم شغّل:

```powershell
adb devices -l
adb shell getprop ro.product.cpu.abilist
adb install -r VideoPocket-probe-arm64.apk
```

4. افتح VideoPocket Probe. انتظر «تم تجهيز المحرك». لا تمنح أي تطبيق كلمات مرور حساباتك؛ هذه النسخة لا تطلبها.

## بوابة النجاح الأولى

استخدم فيديو عامًا قصيرًا تملكه أو تملك إذن تنزيله، ويحتوي على صوت وصورة. لتجربة الدمج استخدم مصدرًا يوفّر مسارات منفصلة مثل فيديو يوتيوب مناسب، وليس ملف MP4 مباشرًا فقط.

1. ألصق رابط الفيديو واضغط «فحص الجودات». دوّن صحة العنوان والمدة والدقات.
2. اختر 360p أو 720p أولًا واضغط «تنزيل الفيديو بصيغته الأصلية». افتح الناتج وتحقق من تشغيله.
3. اختر دقة لها مسار فيديو منفصل واضغط «اختبار دمج المسارين». النتيجة يجب أن تحتوي صوتًا وصورة؛ راقب التزامن في البداية والوسط والنهاية.
4. اضغط «تحويل إلى MP3» عند 192، واستمع للملف. كرر عند 128 و320 إذا نجح الاختبار الأول.
5. جرّب 4K بمقطع قصير إذا كان المصدر يوفّره. غياب 4K من المصدر ليس عطلًا في التطبيق.
6. احفظ تقرير الاختبار من داخل التطبيق، وشارك التقرير مع ملاحظاتك عن التشغيل. التقرير يستبعد الروابط والعناوين؛ اذكر اسم الموقع يدويًا دون إرسال رموز جلسات أو روابط خاصة.

نجاح فحص الملف الآلي لا يثبت تزامن الصوت والصورة؛ الاستماع والمشاهدة خطوة لازمة. وجود QuickJS في الحزمة لا يثبت نجاح استخراج يوتيوب؛ اختبر رابطًا فعليًا.

## اختبارات الفشل

- رابط غير صحيح أو يبدأ بـfile: → رفض قبل تشغيل المحرك.
- ملف محذوف/خاص أو موقع يقيّد الوصول → رسالة فشل بدون كشف الرابط في التقرير.
- انقطاع الإنترنت أثناء الاختبار → تنتهي العملية برسالة؛ أعد الاختبار يدويًا.
- نقص المساحة → رفض أو فشل واضح، وعدم نشر ملف فارغ مكتمل.
- رابط قائمة أو بث جارٍ → مرفوض؛ إذا كان رابط الفيديو يحتوي معرّف قائمة، يعالج المحرك الفيديو الفردي فقط.
- أغلق التطبيق وأعد فتحه بعد اختبار فاشل → يتم تنظيف الملفات المؤقتة التابعة للاختبار؛ لا يوجد استكمال في هذه المرحلة.

اختبارات إطفاء الشاشة والاستكمال والطابور مطلوبة للمرحلة التالية، ولا تدخل في نجاح هذه النسخة التي تعمل في المقدمة فقط.

## قياس الأداء

دوّن طراز الهاتف، إصدار أندرويد، نوع الشبكة وسرعتها المقاسة، الموقع، مدة الفيديو ودقته. تقرير JSON يسجل الزمن الإجمالي لكل عملية وحجم الملف؛ لا يفصل زمن التحويل عن النقل، ولا يقيس زمن أول بايت. لا تعمم النتائج على شبكات ومصادر أخرى.

## 16KB

فحص ELF أثناء البناء يستطيع كشف محاذاة المكتبات، لكنه لا يثبت تشغيلها. يلزم تشغيل الاختبارات على جهاز/بيئة Android بصفحات ذاكرة 16KB أيضًا قبل اعتماد هذا التوافق. قيمة pageSize تظهر في تقرير الهاتف.
